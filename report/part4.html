Частина 4. UI-kit та прототип екранів

Обраний шлях: Варіант B — імплементація в коді (AI-first). UI-kit реалізовано на React + Vite, документація компонентів — у Storybook. Код писався в Claude Code (інструмент, обраний у Частині 1), усі рішення перевірені в браузері.

Структура коду підкреслює реюзабельність: src/styles/tokens.css — єдине джерело кольорів, шрифтів і відступів; src/components/ — компоненти й їхні stories; src/screens/ — екрани, зібрані лише з компонентів UI-kit.

4.2. Design tokens

Усі візуальні значення зібрані в одному файлі tokens.css у три шари: primitives (сира палітра), semantic (ролі: primary, surface, text, success…) і themes (перепризначення ролей). Компоненти посилаються лише на семантичні токени, тому жоден hex-код не зустрічається поза tokens.css (перевірено пошуком по src/).

4.3. Реюзабельність: заміна кольору за кілька хвилин

Це ключова вимога викладача. Щоб замінити синій на зелений, достатньо змінити роль primary в одному місці. У проєкті це вже зроблено як друга тема forest — вона перемикається в тулбарі Storybook (Theme):

/* tokens.css */
[data-theme='forest'] {
  --color-primary: var(--green-600);        /* було navy */
  --color-primary-hover: var(--green-800);  /* було navy-700 */
  --color-primary-active: var(--green-900); /* було navy-950 */
}

Жоден компонент або екран при цьому не змінюється: основні кнопки, активний пункт навігації, повідомлення користувача в чаті й позначка сьогоднішнього дня в календарі перефарбовуються автоматично. Нижче — той самий екран Today у двох темах.

4.6. Навігація та відповідність user flow

Нижня навігація працює на всіх екранах; Vision & Mission і Task Tracker відкриваються з Wheel і мають кнопку «Back to Wheel». Головний сценарій із Частини 2 проходиться в прототипі від початку до кінця:

№Крок user flowЯк це працює в прототипі
1Відкриття Cassiopeia, екран TodayСтарт на Today: прогрес, Top 3, список; якщо завдань немає — порожній стан із кнопкою «Plan with chat»
2Перехід у ChatПункт «Chat» у навігації або кнопка «Plan with chat»
3Ввід вільного текстуПоле повідомлення; кнопка «Use an example» підставляє приклад із PRD
4ШІ аналізуєІндикатор «ШІ думає» близько секунди
5Розгалуження: завдання розпізнано?Ні: відповідь «What exactly needs to be done?» і повтор вводу. Так: картка плану
6Розгалуження: план влаштовує?Назви завдань редагуються прямо в картці, зайве видаляється; порожня назва дає помилку поля й блокує підтвердження
7Підтвердження«Add to my day» → перехід на Today, тост «3 tasks added to your day»
8Кінцеві станиВиконано (чекбокс, закреслення, оновлений прогрес) або перенесено на наступний слот із тостом і дією Undo
Розбір повідомлення ШІ в прототипі імітується простими правилами (src/data/parse.js), бо модель підключається в ПЗ3 через наявний FastAPI-бекенд. Інтерфейс і всі переходи при цьому реальні. Стан «помилка мережі» з user flow покритий компонентом Toast (tone «error»), але в прототипі не викликається, бо мережі немає.

4.8. Висновки

  • Увесь візуальний стиль керується одним файлом tokens.css; друга тема створена трьома перепризначеними змінними ролі primary.
